# Armory "Showroom" (direction B): what was built, 2026-10-18

Branch `armory-next` in `hzm-mod-armory` (worktree of the mod repo), based on `gunfit2-next` @ 553e3337. Code pak only: no art under `textures/`
(the Mills bomb uses the stock `textures/hud/weap_grenade.tga`). Nothing deployed, pushed or hard-deleted. Proof = `proof/` (1080p + 720p shots, contact
sheets, `armory_browse.gif`); raw runs `G:\claude_scratch_archive\armory_build\ab1..ab5` (private harness copy, fair queue, ab5 = the proof run).

## What the player gets
* Category strip with an active state; a big **hero** render with the selected finish applied (finish chips swap the model, as before).
* **Unlocked first** in every picker: guns and grenades (18 card positions, `UNLOCKED n / LOCKED m`), finish chips (STD fixed, then open, then locked),
  uniform / helmet / glove steppers (`<` `>` walk the open pages first, then the locked ones).
* Locked = dimmed card + padlock + what unlocks it (rank abbreviation or the challenge text) + a **progress bar** per card; the hero shows the full text and
  `8750 / 11500 XP` / `74 / 100` with its own bar. No 3D preview for a locked gun (earlier user decision), stats still shown.
* **Compare** (right column): five rows (damage, rate of fire, accuracy, mobility, reload), raw number, the slot's number, a green + / red - / = mark and
  two bars (this gun on top, what the slot holds now below). `n/a` where the files have no value (14 reload times, the three launchers' damage, grenades).
* Click a card = inspect; **EQUIP** commits into the active slot (the old click equipped at once). Equipped = green edge, selected = orange.

## How it is built (all generated; `gen_loadout.py check` EXACT, `gen_lktab.py check` EXACT, `check_mp_isolation.py` 0 FAILED)
* `docs/tools/gen_weapon_stats.py` -> `armory_stats.tsv` from the `.tik` files (+ game paks for the reload `.skc`); committed, so builds need no paks.
* `docs/tools/gen_armory.py` (called by `gen_loadout.py`): card chains, finish chains, compare tables (720 `cm*` files), progress joins, defaults,
  `coop_mod/unlockprog_gen.scr`, `cosring_gen.scr`, `cosorder.scr`. `gen_armory_cos.py` = the stepper side. `gen_armory_urc.py` = `ui/coop_loadout.urc`
  (reads a frozen copy of the old urc, `docs/tools/assets/armory_base.urc`, so every behaviour-bearing widget is carried over verbatim).
* Hand-maintained files that needed a line: `docs/tools/patch_armory_b.py` (init.cfg, s<N>sel.cfg, coop_defaults.cfg, loadoutpick.scr, helmet.scr,
  gloves.scr) and `patch_armory_cos.py` (189 stepper pages; ring recorded in `assets/armory_cos_ring.json`). Idempotent, `check` mode.
* Offline proof of every chain: `docs/tools/cfgsim.py` (a model of the console) + `test_armory_sim.py` / `test_armory_open.py`.
* Fonts: only verdana-12 and facfont-20. Gun boxes all have the aspect of the thumbnail box the fit data was solved for (92x50 = 1.84): hero 150x81,
  card and slot tile 46x25, so `xfmt` is reused unchanged and **no re-solve was needed** (the solver stays the other agent's).

## Engine limits that shaped it (details in docs/TRAPS.md)
A cfg cannot branch, count, copy a cvar or concatenate a name, and widgets cannot move: sorting is a pointer chain over archived command-valued cvars
(`coop_loSrt<id>` etc., pushed by the server like `coop_loCmt<id>`); compare is a join of two unary-encoded levels. Server stufftext: `coop_*` writes are
allowed; `cmd_srvguard.h` (generated by `docs/tools/sec2_guardlist.py`) will list the new vstr'd cvars as VALIDATE entries at the next engine regeneration
(it is already stale on the base branch; unlisted = allowed, so nothing breaks before that). Real text metrics: verdana-12 is a 12-unit cell.
